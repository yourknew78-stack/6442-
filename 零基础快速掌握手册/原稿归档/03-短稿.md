# 03｜UML 与设计模式：读图、分工、落代码

> UML 告诉你**有哪些类、字段和方法**；设计模式告诉你**这些类怎样合作**。

## 先选路线

| 题目里看到 | 去看 |
|---|---|
| 类图、`according to UML` | 第 1、2 节 |
| `getInstance()`、唯一实例 | Singleton |
| 状态图、`XxxState` | State |
| `attach`、`detach`、`update` | Observer |
| `hasNext()`、`next()` | Iterator |
| `Creator`、`createXxx()` | Factory / Template |

## 1. 一个 UML 框怎样变成 Java

```text
Account
-------------------------
- balance : int
-------------------------
+ deposit(amount : int) : void
```

翻译为：

```java
public class Account {
    private int balance;
    public void deposit(int amount) {
        balance += amount;
    }
}
```

UML 写“**名字 : 类型**”，Java 写“**类型 名字**”。

| UML | Java |
|---|---|
| `+` / `-` / `#` | `public` / `private` / `protected` |
| 下划线 | `static` |
| 斜体或 `<<abstract>>` | `abstract` |
| `<<interface>>` | `interface` |
| `*` 或 `0..*` | 多个对象，常用 `List<T>` |

## 2. UML 的线怎样变成类关系

| 线的样子 | 读法 | Java |
|---|---|---|
| 实线空心三角指向 B | A 继承 B | `class A extends B` |
| 虚线空心三角指向 B | A 实现 B 接口 | `class A implements B` |
| 实线连到 B | A 长期持有 B | A 中有 B 类型字段 |
| 空心菱形在 A 端 | A 聚合 B；B 可独立存在 | A 持有 B，常由外部传入 |
| 实心菱形在 A 端 | A 组合 B；B 依附 A | A 持有 B，常自己创建 |
| 虚线普通箭头指向 B | A 临时使用 B | 参数或局部变量 |

B 端写 `0..*`，表示一个 A 对应零到多个 B，常写 `List<B>`。若 UML 的字段格已经列出了 B 字段，**不要因连线再加一份**。字段、方法名和签名按原题精确照抄。

## 3. Singleton：每次取到同一个对象

```java
public class Config {
    private static final Config INSTANCE = new Config();
    private Config() {}
    public static Config getInstance() { return INSTANCE; }
}
```

这三个部件分别负责：保存唯一对象、阻止外部 `new`、提供获取入口。`Config.getInstance() == Config.getInstance()` 应为 `true`。若题目给懒加载骨架，沿用原骨架和字段名。

## 4. State：把行为交给当前状态

灯的状态转换先写成表：

| 当前状态 | 事件 | 下一状态 |
|---|---|---|
| Off | press | On |
| On | press | Off |

`Light` 持有一个 `State`，按按钮时委托当前状态处理：

```java
interface State { State press(); }
class Off implements State { public State press() { return new On(); } }
class On implements State { public State press() { return new Off(); } }
class Light {
    private State state = new Off();
    public void press() { state = state.press(); }
}
```

有的题让状态方法返回下一状态；有的题传入上下文，让状态类调用 `light.setState(...)`。**先读接口签名，再选写法**。若状态类要求 Singleton，转换时用 `On.getInstance()`，不能 `new On()`。图上没有的“状态 + 事件”组合按题目规定处理。

## 5. Observer：变化发生后通知订阅者

Subject 保存 `List<Observer>`。观察者通过 `attach` 登记、`detach` 退出；变化成功后逐个调用 `update`。

```java
interface Observer { void update(String event); }
class Subject {
    private final java.util.List<Observer> observers = new java.util.ArrayList<>();
    public void attach(Observer o) {
        if (o != null && !observers.contains(o)) observers.add(o);
    }
    public void detach(Observer o) { observers.remove(o); }
    public void change() {
        // 先做题目要求的修改
        for (Observer o : observers) o.update("changed");
    }
}
```

是否去重、通知参数和时机，以 README 为准。没发生修改时通常不通知。接口方法在实现类中必须写 `public`。

## 6. Iterator：一个接一个地取

普通列表用下标：`hasNext()` 判断 `index < size`；`next()` 返回 `get(index++)`。`hasNext()` 不前进。

树的前序遍历是“根、左、右”。用栈时：

```java
Node node = stack.pop();
if (node.right != null) stack.push(node.right);
if (node.left != null) stack.push(node.left);
return node.value;
```

栈后进先出，所以**先压右，再压左**。迭代结束后 `next()` 的行为按原题接口决定。

## 7. 其他常见模式，一句话认出

| 模式 | 识别点 | 实现重点 |
|---|---|---|
| Factory Method | 父类声明 `createXxx()` | 子类决定 `new` 哪个具体产品 |
| Template Method | 父类固定几个步骤的顺序 | 变化的步骤交给子类 |
| Facade | 一个入口转调多个子系统 | 入口按题目要求组合调用 |
| Strategy | 多种算法可替换 | 每种算法一个实现，调用方持有接口 |

Factory Method 和 Template Method 可一起出现：父类固定流程调用创建方法，具体创建由子类决定。Strategy 让调用方选择算法；State 随事件转换当前状态。

## 8. 考场顺序

1. 列出所有 class、abstract class、interface、enum。
2. 先写字段、方法签名和可见性；一个 `public` 类一个同名文件。
3. 翻译继承、实现、持有关系，检查字段有没有重复。
4. State 先画转换表；Observer 标出通知时机；Iterator 手走一次顺序。
5. 运行原题测试，先修编译与签名，再修行为。
6. 如果禁止额外字段或方法，逐个核对新加成员。
