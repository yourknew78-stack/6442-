# 04｜易读版 XML 和其他文件格式

> 根据 `exam-practice-questions` 中的原题编写。只选容易入门的部分：看懂格式、读取简单数据、写出简单 XML、解释不同格式的用途。示例会主动缩小题目规模，不代表整道真题的完整答案。

## 1. 先明白：文件格式到底是什么？

假设程序里有一个人：名字叫 John，年龄是 20。

程序运行时，这些数据可以放在变量里。要让程序关闭之后仍能保留数据，就需要把它保存到文件等存储介质中。这叫 **persistence（持久化）**。

**文件格式，就是大家约定“数据在文件里怎么写”。** 同一个人，可以写成下面三种形式。

**CSV：像一张表，一行一条记录。**

```csv
name,age
John,20
```

第一行告诉你两列分别是什么；第二行才是人的数据。逗号把两列隔开。

**XML：用标签包住数据。**

```xml
<person>
    <name>John</name>
    <age>20</age>
</person>
```

`<name>` 和 `</name>` 把名字夹在中间；`<age>` 和 `</age>` 把年龄夹在中间。

**JSON：用“字段名:值”表示数据。**

```json
{"name": "John", "age": 20}
```

`name` 对应 `John`，`age` 对应 `20`。字符串用双引号；这里的数字 `20` 不加引号。

先记住：**数据没有变，只是写法不同。读取文件，就是把这些写法重新变成程序能使用的数据。**

## 2. 最容易掌握的 XML 考点：标签、属性、文本

下面把 2025 S2 Q4 Task A 的数据缩小，方便看清结构：

```xml
<Locations>
    <!-- 第一个地点：里面有子元素，开始标签和结束标签必须成对 -->
    <State name="Victoria">
        <Population>100</Population>
    </State>

    <!-- 第二个地点：里面没有内容，用自闭合标签 /> 直接结束 -->
    <State name="Tasmania"/>
</Locations>
```

逐项对齐：

| XML 中的写法 | 术语 | 白话解释 |
|---|---|---|
| `Locations` | 根元素的标签名 | 最外层的大盒子，包住所有地点 |
| `<State ...>...</State>` | element（元素） | 一个地点的小盒子 |
| `State` | tag name（标签名） | 盒子的种类，这里是“州” |
| `name="Victoria"` | attribute（属性） | 写在开始标签里面的信息 |
| `<Population>100</Population>` | child element（子元素） | 州盒子里面的人口盒子 |
| `100` | text content（文本内容） | 人口盒子里的文字 |
| `<State name="Tasmania"/>` | 空元素的简写 | 等价于 `<State name="Tasmania"></State>` |

**最关键的区分：`name` 是属性，`Population` 是子元素，`100` 是文本。它们的读取方式不同。**

### 2.1 为什么说 XML 像一棵树？

因为一个大盒子可以包含多个小盒子：

```text
Locations                         ← 根元素
├── State，属性 name="Victoria"    ← Locations 的直接子元素
│   └── Population，文本 "100"     ← State 的直接子元素
└── State，属性 name="Tasmania"    ← Locations 的直接子元素
```

`Population` 是 `Locations` 的**后代元素**，但不是它的**直接子元素**。中间还隔着一层 `State`。

### 2.2 看格式就能检查的基础规则

1. 整份 XML 只能有一个根元素。多个地点要放进同一个 `<Locations>` 里。
2. 标签名区分大小写：`Population` 和 `population` 不一样。
3. 开始和结束标签要配对：`<age>20</age>`。
4. 嵌套不能交叉：先打开 `person`，再打开 `age`，就要先关闭 `age`，再关闭 `person`。
5. 属性值要加引号，例如 `name="John"`。

```xml
<!-- 正确：先关里面，再关外面 -->
<person><age>20</age></person>
```

### 2.3 自闭合标签：`/>` 就等于已经关闭

上面的例子里，第二个 `<State>` 用的是**自闭合标签**（Self-closing Tag）。看这两个写法：

**① Victoria：普通标签**

```xml
<State name="Victoria">
    <Population>100</Population>
</State>
```

有开始标签 `<State>`，所以必须有结束标签 `</State>`。

**② Tasmania：自闭合标签**

```xml
<State name="Tasmania"/>
```

注意最后的 `/>`。它等价于：

```xml
<State name="Tasmania"></State>
```

因为里面没有内容，所以可以简写。

**总结**

| 写法 | 含义 |
|---|---|
| `<State>` | 开始标签 |
| `</State>` | 结束标签 |
| `<State/>` | 开始和结束合并 |
| `<State name="Tasmania"/>` | 带属性的自闭合标签 |

记住：XML 中 `/>` 就表示这个元素已经结束，不需要再写 `</State>`。

读 XML 时，自闭合标签仍然是一个正常的元素，只是它没有子元素和文本：`<State name="Tasmania"/>` 照样能用 `getAttribute("name")` 拿到 `Tasmania`，只是它的子节点数为 0（对应 2025 S2 Q4 里 Tasmania 没有 `Population` 的情况）。

## 3. Java 怎么读 XML？先认识这几个工具

**DOM** 在这里可以理解为：Java 先把 XML 文件读进内存，变成一棵可以查询的树。

| Java 名称 | 中文理解 | 在上面的例子中 |
|---|---|---|
| `Document` | 整份 XML 文档 | 整棵树 |
| `Element` | 一个元素 | `State` 或 `Population` 盒子 |
| `Node` | 更一般的“节点” | 可以是元素，也可以是换行等文本节点 |
| `NodeList` | 节点列表 | 一组找到的节点 |

`Node` 的范围比 `Element` 大。**元素是节点，但节点不一定是元素。**

### 先认清“类”和“方法”

“类”可以先理解为 Java 提供的工具或数据类型；“方法”就是让工具或对象做事的命令。

`Document doc`：声明一个 `Document` 类型的变量，名字叫 `doc`，用它保存读出来的整份 XML。

调用方法时，点号左边写要操作的对象，右边写方法名，括号里可以放要交给方法的信息。下面每段只讲一个写法。

### 准备工具并读取文件

`DocumentBuilderFactory.newInstance()`：创建工厂对象，把它存进 `factory`。这个工厂负责制造读取 XML 的工具。

`factory.newDocumentBuilder()`：让工厂制造一个解析器，把它存进 `builder`。`DocumentBuilder` 就是这个解析器的类型。

`new File("locations.xml")`：创建一个代表文件位置的 `File` 对象，指向 `locations.xml`。这一步还没有解析文件。

`builder.parse(new File("locations.xml"))`：让解析器读取并解析刚才指定的文件，得到一份 `Document`，也就是内存中的 XML 树。

### 找到第一个 State

`doc.getElementsByTagName("State")`：从整份文档中找到所有名为 `State` 的元素，结果是一个 `NodeList`。代码把这个列表存进 `states`。

`states.item(0)`：从 `states` 里取第一个节点。Java 的下标从 `0` 开始，所以 `0` 表示第一个。如果列表为空，这里得到 `null`。

`(Element) states.item(0)`：`item(0)` 的返回类型是一般的 `Node`；这里找到的确实是 `State` 元素，所以将它转成 `Element`，存进 `state`，之后才能调用元素特有的 `getAttribute()`。下面的简单例子保证有 `State`；处理不确定的文件时要先检查列表长度。

### 读取属性和标签里的文字

`state.getAttribute("name")`：读取 `<State name="Victoria">` 开始标签中 `name` 属性的值，得到字符串 `"Victoria"`。`String` 是 Java 保存文字的数据类型。

`state.getElementsByTagName("Population")`：只在这个 `State` 里面找名为 `Population` 的后代元素，把找到的元素放进 `NodeList populations`。

`populations.item(0)`：取列表中的第一个 `Population` 节点。如果列表为空，会得到 `null`，所以处理可能缺少人口数据的文件时要先检查列表长度。

`populations.item(0).getTextContent()`：从这个节点读取标签之间的文字。对 `<Population>100</Population>` 来说，得到字符串 `"100"`。

`.trim()`：去掉字符串两端的空白。例如，对 `" 100 "` 调用这个方法，得到 `"100"`。

### 把文字变成数字并输出

`Integer.parseInt("100")`：用 `Integer` 类提供的方法，把字符串 `"100"` 变成整数 `100`，这样才能按数字计算。

`System.out.println(name)`：把变量 `name` 的值打印到屏幕上并换行；在这个例子里打印的是 `Victoria`。

`System.out.println(population)`：把整数变量 `population` 的值打印到下一行；在这个例子里打印的是 `100`。

### 3.1 最小完整例子：读出 Victoria 和 100

先把下面内容保存为 `locations.xml`。这里故意只保留一个有完整人口数据的地点。

```xml
<Locations>
    <State name="Victoria">
        <Population>100</Population>
    </State>
</Locations>
```

下面是独立的教学程序，保存为 `ReadXmlDemo.java`。它假设输入就是上面的简单结构。

```java
import java.io.File;
import javax.xml.parsers.DocumentBuilder;
import javax.xml.parsers.DocumentBuilderFactory;
import org.w3c.dom.Document;
import org.w3c.dom.Element;
import org.w3c.dom.NodeList;

public class ReadXmlDemo {
    public static void main(String[] args) throws Exception {
        // 1. 准备一个能读取 XML 的工具。
        DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
        DocumentBuilder builder = factory.newDocumentBuilder();

        // 2. 读取文件，得到内存里的 XML 文档。
        Document doc = builder.parse(new File("locations.xml"));

        // 3. 找到所有标签名为 State 的元素。
        NodeList states = doc.getElementsByTagName("State");

        // 4. 取第一个 State；列表下标从 0 开始。
        Element state = (Element) states.item(0);

        // 5. 从开始标签里面取 name 属性。
        String name = state.getAttribute("name");

        // 6. 在这个 State 里面找 Population 元素。
        NodeList populations = state.getElementsByTagName("Population");
        String text = populations.item(0).getTextContent().trim();

        // 7. 把文字 "100" 转成可以计算的整数 100。
        int population = Integer.parseInt(text);

        System.out.println(name);
        System.out.println(population);
    }
}
```

把两个文件放在同一文件夹，在这个文件夹执行 `javac ReadXmlDemo.java`，再执行 `java ReadXmlDemo`，输出：

```text
Victoria
100
```

这里的 `import` 是告诉 Java 使用哪些现成工具；`main` 是程序的入口。教学程序中的 `throws Exception` 表示把读取失败等异常交给调用方处理。**考试时不能擅自给题目提供的方法加上它**；例如 2025 S2 Q4 明确禁止修改方法签名，并要求出错时返回 `null`。

### 3.2 整段程序按执行顺序走一遍

一句话概括这段代码：**Java 打开一个 XML 文件，找到第一个 State，读出它的名字和人口，打印出来。**

下面按执行顺序，把它拆成八个动作。

**① 先造一个“读 XML 的工具”**

XML 解析工具（例如 DOM 和 SAX）可以直接把 XML 文件解析成结构化的数据，让程序识别出 Element（元素）、Attribute（属性）、Text（文本）等，**不需要程序员自己逐字节解析**。所以第一步是申请一个这样的解析器，也就是下面这两行。

```java
DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
DocumentBuilder builder = factory.newDocumentBuilder();
```

两个对象分工不同：

| 对象 | 作用 |
|---|---|
| `factory` | 工厂：负责生产解析器 |
| `builder` | 读取工具：真正负责读 XML |

顺序是 `factory`（工厂）→ 制造 `builder`（读取工具）。这两行是固定开头，照抄即可。

本节用的 `DocumentBuilder` 属于 **DOM** 这一派：把整份文件读进内存、建好树，之后再慢慢查。另一个常听到的名字是 **SAX**：边读边处理，不建树，读完就过去了，所以适合特别大的文件。本文只用 DOM，SAX 知道“同样是解析器，只是做事方式不同”即可。

**② 读取文件，变成内存里的一棵树**

```java
Document doc = builder.parse(new File("locations.xml"));
```

拆开看：

- `new File("locations.xml")`：指定要读的文件，相对路径，文件要放在运行程序时的当前目录里。
- `builder.parse(...)`：读取并解析这个文件。
- `Document doc`：保存解析结果，也就是整份 XML 文档。

执行完这一行，XML 已经变成内存中的一棵树，后面的代码都在这棵树上查东西。

**③ 找出所有名为 State 的元素**

```java
NodeList states = doc.getElementsByTagName("State");
```

`getElementsByTagName("State")` 的意思是：**从整份文档里找出所有标签名为 `State` 的元素**，放进一个 `NodeList`（节点列表）。

如果文件是第 2 节那份带两个地点的 XML，`states` 里就有两项：

| 下标 | 内容 |
|---|---|
| `0` | `<State name="Victoria">…</State>` |
| `1` | `<State name="Tasmania"/>` |

列表下标从 `0` 开始，所以第一个是 `0`，不是 `1`。

**④ 取出第 0 个节点，并当作 Element 使用**

```java
Element state = (Element) states.item(0);
```

两句分开看：

- `states.item(0)`：从列表里取第 0 个节点，也就是 Victoria 那个 State。
- `(Element)`：强制类型转换，把节点当作元素来用。

为什么要转？因为 `item(0)` 的返回类型是 `Node`，而 `Node` 不保证有 `getAttribute()` 这类元素方法；下一步要用元素的方法，所以先转成 `Element`。这里按标签名找出来的节点确实都是元素，转换不会出错。

**⑤ 读开始标签里的属性**

```java
String name = state.getAttribute("name");
```

对照 XML 这一行：

```xml
<State name="Victoria">
```

- `State`：元素（标签）名；
- `name`：属性名；
- `Victoria`：属性值。

`getAttribute("name")` 到开始标签里找名叫 `name` 的属性，返回字符串 `"Victoria"`。**属性是写在尖括号里面的，不需要 `getTextContent()`。**

**⑥ 在这个 State 内部找 Population，再取里面的文字**

```java
NodeList populations = state.getElementsByTagName("Population");
String text = populations.item(0).getTextContent().trim();
```

第一行：`state.getElementsByTagName("Population")` 是在**这个 State 里面**找，不是从整份文档找，所以只会拿到 Victoria 自己的 `<Population>100</Population>`。

第二行连了三个动作，从左往右执行：

| 代码 | 得到什么 |
|---|---|
| `populations.item(0)` | 第一个 Population 元素 |
| `.getTextContent()` | 元素里的文字 `"100"` |
| `.trim()` | 去掉两端空白；若原来是 `" 100 "`，就变成 `"100"` |

最后 `text` 保存的是字符串 `"100"`。

**⑦ 把文字转成整数**

```java
int population = Integer.parseInt(text);
```

XML 里读出来的一律是文字，`Integer.parseInt("100")` 把它变成能参与计算的整数 `100`。

区别很直观：

- `100 + 1` → `101`
- `"100" + 1` → `"1001"`（字符串拼接）

**⑧ 打印结果**

```java
System.out.println(name);
System.out.println(population);
```

输出：

```text
Victoria
100
```

**把整个流程连起来**

```text
locations.xml
   │  builder.parse(...)
   ▼
Document（整份文档，一棵树）
   │  getElementsByTagName("State")
   ▼
NodeList states
   │  item(0)          ← 取第一个；想全部要就写循环（见 4.1）
   ▼
Element state（Victoria）
   ├─ getAttribute("name")                     → "Victoria"
   └─ getElementsByTagName("Population")
        │  item(0)
        ▼
      Population 元素
        │  getTextContent().trim()              → "100"
        ▼
      Integer.parseInt(...)                     → 100
```

**这段程序里，考试最值得记住的五个方法**

| 方法 | 作用 |
|---|---|
| `parse(file)` | 读取 XML，得到 `Document` |
| `getElementsByTagName("X")` | 找出所有标签名为 X 的元素 |
| `item(0)` | 取列表中的第 0 个节点 |
| `getAttribute("name")` | 读开始标签上的属性值 |
| `getTextContent()` | 读元素里面的文字 |

**最容易混的一处**，都来自同一段 XML：

```xml
<State name="Victoria">
    <Population>100</Population>
</State>
```

- `state.getAttribute("name")` → `"Victoria"`：读**标签上**的属性；
- `populations.item(0).getTextContent()` → `"100"`：读**标签里**的文字。

属性用 `getAttribute`，文字用 `getTextContent`，两者不能互换。

**最后一个坑**：这段程序只读 `item(0)`，所以 Tasmania 没有人口也不会出错。但一旦改成循环读所有 State，就必须先判断 `populations.getLength() > 0`，否则 Tasmania 那一轮会在 `item(0)` 上抛出 `NullPointerException`；写法见 4.2。

## 4. 在简单读取上，再掌握三个小变化

### 4.1 多个元素：用循环逐个读

一句话概括：**XML 里有多个 State，用 `for` 循环把它们一个一个取出来，打印名字。**

**① 假设 XML 文件长这样**

```xml
<Locations>
    <State name="Victoria"/>
    <State name="Tasmania"/>
</Locations>
```

解析器读进来以后，`states` 里就有两项，可以想成一张带下标的表：

```text
states（NodeList）
├─ 下标 0 → <State name="Victoria"/>
└─ 下标 1 → <State name="Tasmania"/>

states.getLength() = 2
```

**② 逐行解释**

这段接在 3.1 取得 `states` 的代码之后使用：

```java
for (int i = 0; i < states.getLength(); i++) {
    Element state = (Element) states.item(i);
    String name = state.getAttribute("name");
    System.out.println(name);
}
```

**第一行：`for (int i = 0; i < states.getLength(); i++)`**

`i` 从 `0` 开始，每轮加 1；只要 `i < states.getLength()` 还成立，就继续下一轮，直到所有 State 都走完。

**第二行：`Element state = (Element) states.item(i);`**

- `states.item(i)`：取列表中第 `i` 个节点；
- `(Element)`：把节点转换为 `Element` 类型，理由和 3.2 的 ④ 一样；
- `state`：保存这一轮取出来的元素。

**第三行：`String name = state.getAttribute("name");`**

从当前 State 元素中读取 `name` 属性。例如面对：

```xml
<State name="Victoria"/>
```

得到 `name = "Victoria"`。自闭合标签没有子元素，但属性照样能读。

**第四行：`System.out.println(name);`**

把这一轮的名字打印出来。

**③ 看看循环是怎么执行的**

| 执行到哪一步 | `i` 的值 | 做什么 | 输出 |
|---|---|---|---|
| 第一轮 | `0` | 取第 0 个 State，读 `name` 属性 | Victoria |
| 第二轮 | `1` | 取第 1 个 State，读 `name` 属性 | Tasmania |
| 下一次判断 | `2` | `2 < 2` 不成立，循环结束 | 没有输出 |

注意：循环结束时 `i` 的值是 `2`，但列表里没有 `item(2)`，所以第二轮之后不会再取第三个。

**最重要的是记住三个方法：**

| 写法 | 作用 |
|---|---|
| `states.getLength()` | 列表里一共有几个元素 |
| `states.item(i)` | 取第 `i` 个元素，索引从 0 开始 |
| `state.getAttribute("name")` | 读这个元素的 `name` 属性 |

**核心就是：先从列表里取 Element，再从 Element 里取 Attribute。**

`getLength()` 是列表长度；`i++` 是把 `i` 加 1。

### 4.2 人口可能没有：先判断，再取值

2025 S2 Q4 Task A 要求：人口缺失或空白时，对应的值为 `null`，**不能自己改成 0**。`0` 表示确定人口是零；`null` 表示这里没有人口数据。

下面是处理一个 `state` 的局部片段，假设它符合题目的平铺结构，至多有一个 Population：

```java
NodeList populations = state.getElementsByTagName("Population");
Integer population = null;

if (populations.getLength() > 0) {
    String text = populations.item(0).getTextContent().trim();
    if (!text.isEmpty()) {
        population = Integer.parseInt(text);
    }
}
```

- `Integer` 可以保存整数，也可以保存 `null`；`int` 不能保存 `null`。
- `getLength() > 0`：确实找到了 Population，才去取第一个。
- `text.isEmpty()`：文字是不是空的；前面的 `!` 表示“不是”。

代入三种输入：

| 输入 | 执行过程 | 最后得到 |
|---|---|---|
| 没有 Population | 列表长度为 0，不进入外层 `if` | `null` |
| `<Population> </Population>` | 去空白后是 `""`，不进入内层 `if` | `null` |
| `<Population>100</Population>` | 找到元素，文字非空，转换成整数 | `100` |

这段只处理“缺失和空白”。如果文字是 `abc`，整数转换会抛出异常；如果出现多个 Population，也需要按原题另做格式检查。

### 4.3 只要直接子元素时，别把所有后代都找出来

`getElementsByTagName("State")` 会向下寻找所有同名后代，**不是只找下一层**。

2025 S2 Q4 Task A 还明确说：地点的标签名不一定叫 `State`。因此，完整答题不能只搜 `State`，应遍历根元素的直接子节点，筛出元素：

```java
Element root = doc.getDocumentElement(); // 拿到最外层 Locations
NodeList children = root.getChildNodes(); // 只拿下一层节点

for (int i = 0; i < children.getLength(); i++) {
    org.w3c.dom.Node node = children.item(i);
    if (node.getNodeType() != org.w3c.dom.Node.ELEMENT_NODE) {
        continue; // 不是元素就跳过，例如缩进换行产生的文本节点
    }
    Element location = (Element) node;
    String name = location.getAttribute("name");
    System.out.println(name);
}
```

**为什么要筛选？** XML 为了好看写了换行和空格，这些也可能进入节点列表。不能直接把所有 `Node` 都强制转换为 `Element`。

知道这个区别即可。本节没有展开 Task A 的完整格式校验，也不展开 Task B 的递归建树。

## 5. 写 XML：创建盒子 → 放内容 → 接到树上 → 保存

读文件是“文件 → 内存”；写文件是“内存 → 文件”。

下面是独立程序，保存为 `WriteXmlDemo.java`。它把一个人的名字写到 `person.xml`。

```java
import java.io.File;
import javax.xml.parsers.DocumentBuilderFactory;
import javax.xml.transform.Transformer;
import javax.xml.transform.TransformerFactory;
import javax.xml.transform.dom.DOMSource;
import javax.xml.transform.stream.StreamResult;
import org.w3c.dom.Document;
import org.w3c.dom.Element;

public class WriteXmlDemo {
    public static void main(String[] args) throws Exception {
        Document doc = DocumentBuilderFactory.newInstance()
                .newDocumentBuilder().newDocument();

        Element person = doc.createElement("person"); // 创建 person 盒子
        doc.appendChild(person);                      // 把它接成根元素

        Element name = doc.createElement("name");     // 创建 name 盒子
        name.setTextContent("John");                  // 把 John 放进去
        person.appendChild(name);                     // 把 name 接到 person 里面

        Transformer writer = TransformerFactory.newInstance().newTransformer();
        writer.transform(new DOMSource(doc), new StreamResult(new File("person.xml")));
    }
}
```

执行 `javac WriteXmlDemo.java`，再执行 `java WriteXmlDemo`，会生成 `person.xml`。忽略 XML 声明和排版空白，其结构是：

```xml
<person><name>John</name></person>
```

最后两行可作为保存文件的固定写法理解：`DOMSource(doc)` 是要保存的文档；`StreamResult(...)` 是输出到哪里；`transform(...)` 执行输出。

**最容易漏的是 `appendChild`。** `createElement` 只是新建一个盒子；还要把它接到文档树上，才能随这棵树一起保存。

如果题目要求的是属性，例如 `<person name="John"/>`，则在保存前使用 `person.setAttribute("name", "John")`，而不是创建 `<name>` 子元素。两种写法不能随意互换，必须照题目给的格式。

## 6. CSV 最容易掌握的考点：分隔符、表头、类型转换

2020 S2 Q3 给的是下面这种格式，**实际分隔符是分号 `;`**：

```text
id;name;age;occupation
33;John;20;Student
```

第一行是 **header（表头）**，说明每一列的含义。读取人的数据时要跳过它，否则把 `"id"` 当整数转换就会报错。

先只练第二行，不急着写整个文件读取程序：

```java
String line = "33;John;20;Student";
String[] parts = line.split(";");

int id = Integer.parseInt(parts[0]);
String name = parts[1];
int age = Integer.parseInt(parts[2]);
String occupation = parts[3];
```

`String[]` 表示一组字符串；`split(";")` 表示“遇到分号就拆开”。拆开之后是：

| 数组位置 | 得到的文字 | 转换后的变量 |
|---|---|---|
| `parts[0]` | `"33"` | 整数 `id = 33` |
| `parts[1]` | `"John"` | 字符串 `name = "John"` |
| `parts[2]` | `"20"` | 整数 `age = 20` |
| `parts[3]` | `"Student"` | 字符串 `occupation = "Student"` |

原题已经提供 `Person` 类，构造方法按 `id, name, age, occupation` 的顺序接收四个值，因此在原题环境中可以接着写：

```java
Person person = new Person(id, name, age, occupation);
```

它表示“用刚才拆出来的四个值创建一个人”。

**做这类基础题，先检查三个地方：有没有跳过表头、分隔符是什么、哪些列需要转成数字。**

这里的 `split` 适用于题目展示的简单记录。遇到带引号、字段内部含分隔符的复杂 CSV，不能把这个写法当作通用解析器。2020 S2 Q3 后续还涉及红黑树和指定遍历顺序，本篇只学习容易掌握的拆行部分。

## 7. 其他格式：先会看、会说用途

2023 S2 Q3 明确列出 JSON、XML、CSV 和 Bespoke。这里先掌握最基本的区别。

| 格式 | 最容易记的特点 | 适合表达什么 |
|---|---|---|
| CSV | 行和列，通常较简洁 | 每条记录有相同字段的表格，例如学生名单 |
| XML | 标签、属性，可以层层包含 | 有层级的数据，例如国家包含州、州包含城市 |
| JSON | 字段名与值，支持对象和数组 | 有结构的数据，例如一个学生及其课程列表 |
| Bespoke | 专门为某个应用约定的格式 | 按该应用自己规定的规则读写 |

**JSON 再认识两个符号就够了：**

```json
{
  "name": "John",
  "courses": ["Java", "Maths"]
}
```

- `{ ... }`：一个对象，可以先理解为“一条包含多个字段的记录”。
- `[ ... ]`：一个数组，可以先理解为“按顺序列出的多个值”。
- `courses` 的值是一组课程，里面有 `Java` 和 `Maths`。

**Bespoke 不代表某个统一的语法。** 例如某应用规定用 `John|20` 保存一个人，这就是一种自定义格式；读取时必须知道 `|` 是分隔符，第一项是名字，第二项是年龄。这是自拟例子，不是原题规定。

### 7.1 真题问“多种格式怎么设计”，最容易理解的回答

不要先背模式名。先想：XML、CSV 和 JSON 的写法不一样，因此读取步骤也不同；但读完以后，我们都希望得到应用能使用的数据。

可以约定所有读取器都有一个 `read` 操作，再分别编写 `XmlReader`、`CsvReader` 和 `JsonReader`。主程序选择合适的读取器，调用相同的操作。

```text
XML 文件  → XmlReader  ┐
CSV 文件  → CsvReader  ├→ 转成应用约定的数据形式
JSON 文件 → JsonReader ┘
```

这种把不同读取方法做成可替换实现的思路，可以用 **Strategy（策略模式）** 表达。选择创建哪个读取器，还可以交给工厂处理。本篇只记住“不同格式各自负责解析、对外使用共同接口”这个核心。

对应 2023 S2 Q3a，可以这样写一段基础回答（这是答题示例，不是官方答案）：

> 定义统一的数据读取接口，让 XML、JSON 和 CSV 读取器分别实现它。主程序通过接口调用读取方法，可以替换不同的解析策略。这属于策略模式的思路。添加新的文件格式时，可以新增读取器实现，减少对已有解析代码的修改，并方便分别测试各个读取器。

这只是基础论述；完整题目仍要按其要求解释具体设计及代码质量收益。

**① `<student age="20">John</student>` 中，哪个是标签名、属性、文本？**

答案：不应该。这道题实际使用分号，应写 `split(";")`。

### 2025 S1｜Q4 第 7 题：分片为什么容易用 CSV 表达

#### 题目（原题内容）

```text
Q7 [Persistent Data] 
A client wishes to apply “sharding” to a large amount of data persistently. Sharding is the

c. JSON is suitable, as it has native support for sharding through the GSON Java library. 
d. Serialization is suitable only if the objects are each less than 128 bytes in size. In this case,

```

#### 逐步讲解与做题套路


原题：[MC_Questions_2025_S1.pdf](../exam-practice-questions/past-exams/2025-1/src/Q4/MC_Questions_2025_S1.pdf)。

**题目要什么？** 把一个大文件拆成多份可独立访问的小文件。例如 10,000 条记录拆成 10 份，每份 1,000 条。这叫 sharding（分片）。在给定的四个“格式 + 理由”选项中选正确的一项。

**先想最小例子：**

```text
原文件：表头 + 第1条 + 第2条 + 第3条 + 第4条
分片A：表头 + 第1条 + 第2条
分片B：表头 + 第3条 + 第4条
```

对于这里简单、每条记录独立的 CSV，按完整记录边界分开，就不需要继承上一片里尚未闭合的 XML 标签层级。因此本题选 **A**。

**其他理由为什么不成立？**

- B：XML 支持属性，不等于属性自动实现分片。每份仍要处理正确的标签结构和完整文档。
- C：JSON/GSON 不会因为采用 JSON 就自动得到题目描述的分片机制。
- D：Java 序列化没有题目所说“对象必须小于 128 字节才可这样保存”的限制。

**不要扩大结论：** 不是“XML、JSON 永远不能分片”。它们也可以由程序组织成多个合法文件；只是原题 B/C/D 给出的理由不成立。复杂 CSV 的一个带引号字段还可能跨物理行，所以不能把“完整记录”一概等同于“每个换行”。

**做题套路：先解释操作是什么 → 检查每份能否独立解释 → 连同选项的理由一起判断 → 不把某题答案背成绝对禁令。**

#### 逐步讲解与做题套路


原题：[说明](../exam-practice-questions/past-exams/2020-2/Q3/README.md) · [Application.java](../exam-practice-questions/past-exams/2020-2/Q3/Application.java) · [Person.java](../exam-practice-questions/past-exams/2020-2/Q3/Person.java)。本节讲文件转换，红黑树及层序算法不展开。

**题目要什么？** 读分号分隔的 CSV，建立 Person 列表；再把树中给定顺序的人写入 people.xml。

先处理简单部分 readCsv。原格式：

```text
id;name;age;occupation
33;John;20;Student
11;Jerry;40;Lecturer
```

**逐步做第一条数据：**

1. 跳过表头 `id;name;age;occupation`。
2. `"33;John;20;Student".split(";")` 得到四个字符串。
3. 第 0 列和第 2 列转成整数 33、20。
4. 按构造方法顺序创建 `new Person(33, "John", 20, "Student")`。
5. 加入列表；然后对 Jerry 重复一次。

在原题已有 `list` 的前提下，可编辑区的一种参考写法：

```java
try (java.io.BufferedReader reader = new java.io.BufferedReader(
        new java.io.FileReader(fileName))) {
    reader.readLine(); // 跳过表头
    String line;
    while ((line = reader.readLine()) != null) {
        if (line.trim().isEmpty()) continue;
        String[] parts = line.split(";", -1);
        Person person = new Person(Integer.parseInt(parts[0]), parts[1],
                Integer.parseInt(parts[2]), parts[3]);
        list.add(person);
    }
} catch (java.io.IOException e) {
    throw new java.io.UncheckedIOException(e);
}
```

原方法末尾的 `return list;` 保留。`split(";", -1)` 让末尾空字段也保留下来；这是简单无引号记录的写法，不是通用 CSV 解析器。这里针对原题规定的有效格式；文件 IO 异常转为非受检异常是该片段的处理选择，并非原题指定的唯一策略。

**写 XML 时，先记住两层循环的形状：** 根 people 只创建一次；每个人创建一个 person；每个 person 里按要求放 id、name、age、occupation。

对 John 应生成：

最后保存到原题明确指定的 `people.xml`。注意本题根为 **people**，2021 S2 是 **persons**，不能跨题照抄名字。

**顺序也属于答案。** 原题要求右到左的层序顺序，给定例子是 `33,88,11,43,16,10`；不是 CSV 原顺序 `33,11,88,10,16,43`。`saveXML` 骨架已取得 `tree.levelTraversal()` 的列表，应按该列表顺序写。即使 XML 语法正确，人员顺序错了仍不符合题目。
