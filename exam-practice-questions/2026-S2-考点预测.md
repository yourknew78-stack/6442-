## 三、编程题

### 1. Tokeniser + Parser（把握：高）

依据：

- 12 套真题里有 11 套出了这类代码大题。唯一没出的是 2025 S2，那一套只有两道编程题；今年有三道。
- 散题里有 3 道（q2、q5、q10）。

预计的题面（按最近三次：2024 S1、2024 S2、2025 S1）：

- README 给出 CFG 文法；Task A 实现 `Tokeniser.next()`，Task B 实现 `Parser.parse()`。
- Parser 要返回对象，例如 2025 S1 的 `IntExp` / `VarExp` / `OpExp` / `SeqExp`，2024 S2 的 `GitCommand` 列表。输入不合文法时整体返回 `null`，即使前半段合法也不行。
- 反复出现的细节：token 之间可以没有空格，也可以有多个空格；大小写敏感；遇到不认识的字符串返回 `null`；只能在 `Tokeniser.java` 和 `Parser.java` 里加辅助方法，不能加字段。

散题的风格不同：`parseExp()` 只判断输入是否合文法，返回 `true` / `false`（q2 的 `S := YXS | Y`，q5 的括号匹配 `S := () | (S) | SS`，q10 的奇偶数字文法）。两种都练一遍。

要练到能独立写出来的内容：

- 一条文法规则对应一个解析方法（递归下降）。
- 右递归规则，如 `<SingleExp> := <Value> <OP> <SingleExp> | <Value>`。
- 用分隔符连接的序列，如 `<GitCommand><Sep> <GitCommands>`，包括末尾分隔符可有可无的情况。
- 解析结束后还剩 token 时判为不合法。

对应章节：[第 6 章](../零基础复习手册/06-tokeniser-parser.md)。

### 2. 设计模式，按 UML 实现（题型把握：高）

各模式出现的位置：

| 模式 | 真题代码题 | 散题 |
|---|---|---|
| State | 2022 S1、2023 S1、2025 S1 | q4、q12 |
| Singleton | 2022 S1、2025 S1 | q4、q8 |
| Observer | 2023 S1、2025 S2 | 无 |
| Iterator | 2021 S2、2024 S2 | q13 |
| 工厂方法 / 模板方法 | 2023 S2、2024 S1 | 无 |
| Facade | 未考过 | q15 |

最近四套卷的模式题依次是：工厂方法 + 模板方法、Iterator、State + Singleton、Observer，没有连续两次考同一个模式。按这个规律：

- Observer 刚在 2025 S2 考过，连考的可能性较低。
- State + Singleton 是出现次数最多的组合，真题 3 次、散题 2 次，最值得练熟。
- Iterator 和工厂方法都是 2024 年考的，轮回来的可能性不小。
- Facade 只在散题里出现。提示说风格和题库相近，所以也要会；它最简单，看一遍 q15 就够。

这个轮换规律只有四个样本，不足以押某一个模式。六个模式的骨架都要能不看资料写出来，练习时间按上面的顺序分配。

2025 S2 的模式题有三个新要求，今年可能沿用：

- 大部分类文件要自己新建（只给了 `FavouriteList` 的一部分代码），不是在给好的骨架里填空。
- 类名、字段名、方法签名必须和 UML 完全一致，包括大小写。
- 除构造器、getter、setter 外，不能多加字段和方法。

所以读 UML 类图要准：可见性符号（`+` `-` `#`）、抽象类与接口、静态成员、继承与实现的箭头、关联的方向和多重性。散题 q12（自动售货机）同时给了类图和状态转换图，适合练「看图建类」。

对应章节：[第 8 章](../零基础复习手册/08-design-patterns.md)、[第 3 章](../零基础复习手册/03-uml-solid-refactoring.md) 的 UML 部分。

### 3. 树，可能搭配持久化（把握：中高）

依据：12 套真题的代码题全都涉及树。最近四套依次是：为 AVL 树设计测试数据（2024 S1）、BST 前序迭代器（2024 S2）、左右反向插入的家族树（2025 S1）、把嵌套 XML 读成多叉树（2025 S2）。

近年的出法是给一棵规则被改过的树，考递归，而不是默写标准 BST。常见的小问：

- `find`、`insert`，比较方向按题目规定，可能和标准 BST 相反。
- 校验整棵树是否有序（`isOrdered`，递归时带上下界）。
- 递归求高度或层级。先看清题目的定义，2025 S1 把叶子算作第 1 层。
- 按深度缩进打印整棵树（2025 S1 的 `show`、2023 S2 的 `toString`）。
- 遍历的变体：前序、反前序（根、右、左）、从右到左的层序、用栈实现的迭代遍历。
- 对满足条件的节点求和或拼接（散题 q6、q9：有奇数个直接子节点的节点）。

历年真题没有要求手写旋转代码，用到旋转的题（2020 S2、2024 S1）旋转方法都是给好的。AVL 和红黑树的旋转要会在纸上推演，用来做选择题和设计测试数据。

持久化这部分：

- XML（`org.w3c.dom`）在 6 套真题里考过代码，2025 S2 单独占了一整题。要会读属性、读子元素文本、递归读嵌套结构、处理缺失的可选字段、出错时返回 `null`；写文件也要会（散题 q7、q14 读写都考）。
- JSON 在真题里没有考过代码，但散题有两道（q1、q11：读入、合并重名记录、写回）。另外 2025 S2 的考试仓库里带了 `gson` 和 `json-simple` 两个 jar，当时没有题目用到。JSON 是冷门，但读写各练一遍比较稳妥。
- CSV 和纯文本的读取各考过一次（2020 S2、2023 S1），会用 `BufferedReader` 逐行读即可。

对应章节：[第 9 章](../零基础复习手册/09-trees.md)、[第 7 章](../零基础复习手册/07-persistence.md)。

## 四、测试题

题型把握高：最近三次测试题（2024 S1、2024 S2、2025 S2）都是 JUnit4 参数化测试，考生要写的是 `data()` 里的用例表。`@RunWith(Parameterized.class)`、`@Parameterized.Parameters`、`Arrays.asList(new Object[][]{...})` 这套写法要能直接写出来。

两种形式都可能出：

| 形式 | 出现的年份 | 要做的事 |
|---|---|---|
| 白盒：最少分支覆盖 | 代码题 7 次（2019 S1、2019 S2、2020 S1、2020 S2、2021 S2、2023 S1、2025 S2）；选择题 2 次（2024 S1、2025 S1） | 读给定方法，用最少的用例走遍每个分支，并算出每个用例的期望返回值 |
| 黑盒：区分正确与错误的实现 | 2024 S1（AVL）、2024 S2（`HashingBox`） | 只看规格说明，设计用例让错误实现至少挂一个，正确实现全过 |

白盒出现的次数多得多，最近一次也是它，优先练。2019 年的两套还考过语句覆盖（题面叫 code coverage），要分清它和分支覆盖的区别。

白盒的评分规则（2025 S2）：

- 用例比最少数量多一个或少一个，各扣 5 分；分支覆盖不到 50% 整题没分。
- 不能写会让被测方法抛异常的用例。
- 期望值必须和给定实现的实际返回值一致，哪怕实现本身不合常理。
- `&&` 和 `||` 的每个子条件单独算分支（2020 S2 题面明确写了）。
- 先画控制流图，再列覆盖表，最后合并用例。注意提前 `return` 会让后面的分支走不到，这类分支需要单独的用例。

黑盒的评分规则（2024 S2）：

- 把正确实现判错，比放过一个错误实现扣分重得多。期望值必须自己按规格算准。
- 用例要覆盖边界值（范围的两端及刚好越界）、规格里每条特殊规则、应当抛异常的情况。
- 2024 S1 还要求所有测试树的节点总数最少，做法是四种旋转各用一棵最小的树。

对应章节：[第 5 章](../零基础复习手册/05-testing.md)。

## 五、选择题

题库里有三组选择题（2024 S1 共 14 道、2025 S1 共 10 道、2025 S2 共 5 道）。各主题出现的情况：

| 主题 | 2024 S1 | 2025 S1 | 2025 S2 | 考过的具体内容 |
|---|---|---|---|---|
| 树 | 考 | 考 | 考 | BST 依次插入后的高度；红黑树插入后的颜色、旋转和遍历结果；AVL 插入后做哪种旋转 |
| CFG 文法 / Tokenisation | 考 | 考 | 考 | 判断哪个输入不合文法；语法树的根节点；终结符与非终结符；Tokenisation 的概念 |
| Android | 考 | 考 | 考 | Activity 生命周期与返回栈；多语言资源（`values-es/strings.xml`） |
| 白盒分支覆盖 | 考 | 考 | 未考 | 数一个函数的分支数；按控制流图求最少用例数 |
| Singleton | 未考 | 考 | 考 | 私有构造器；`getInstance()` 与 `static`；`assertSame` |
| 契约式设计 / JML | 未考 | 考 | 考 | JML 注解的写法；JML 能做什么、不能做什么 |
| 知识产权 | 考 | 考 | 未考 | 澳洲的版权、专利、Copyleft；GitHub 上没有许可证的代码能不能用 |
| SOLID | 考（OCP） | 考（LSP，题目标签是 Refactoring） | 未考 | 哪种设计符合开闭原则；怎样扩展类才不违反里氏替换 |
| 代码坏味道与重构 | 考 | 未考 | 未考 | 找出代码里的坏味道并选对重构方法 |
| UML 类图 | 考 | 未考 | 未考 | 组合、聚合、继承、多重性的判断 |
| 职业道德（IEEE） | 考 | 未考 | 未考 | 判断情境是否符合 IEEE 道德准则 |
| Git | 未考 | 考 | 未考 | 读 `git log --graph` 的输出，判断合并历史 |
| 持久化格式 | 未考 | 考 | 未考 | CSV / XML / JSON / 序列化哪种适合分片 |
| 软件构造的范围 | 考 | 未考 | 未考 | 哪些活动属于软件构造 |

预测：

- 树、CFG 文法、Android 三组都考了，今年大概率还有。
- 2025 S2 有白盒测试代码题时，选择题里就没有测试题。今年测试单独成题，选择题再考测试的可能性较低。
- 今年没有开放题，SOLID、坏味道与重构、知识产权、职业道德回到选择题的可能性升高。SOLID 在选择题里只考过 OCP 和 LSP，另外三条（SRP、ISP、DIP）也要能判断。
- 「性能分析」在 2024 S2 开放题的官方主题列表里，但题库里没有出过选择题，属于没被考过的正式主题。

答题时先看清是单选还是多选：2024 S1 是多选，全对才得分；2025 S1 全部单选；2025 S2 有「select all the correct statements」的题。

提示说选择题和平时练的风格相近，所以每周的选择题练习是比真题更直接的来源，考前应当全部重做一遍。这部分材料不在本文件夹里，上面的表没有包含它。

对应章节：[第 4 章](../零基础复习手册/04-mcq.md)，树和文法的选择题分别在第 9 章和第 6 章。

## 六、复习顺序建议

五道题里有四道要写代码，建议按下面的顺序分配时间：

1. **Tokeniser + Parser**：最稳定的大题，分值也常是全卷最高（2019 S1、2019 S2、2020 S2、2022 S1、2024 S1 都是 30 分）。至少独立重做 2024 S2 和 2025 S1 两道。
2. **测试题**：题型固定，练熟就能拿分。重做 2025 S2 Q2（白盒）和 2024 S2 Q2（黑盒）。
3. **设计模式 + UML**：State + Singleton、Iterator、工厂方法、Observer、Facade，每个模式不看资料写一遍骨架。重做 2025 S2 Q5，练习严格按 UML 建类。
4. **树的递归操作**：重做 2025 S1 Q2 和 2024 S2 Q1。
5. **XML 读写**：重做 2025 S2 Q4 和散题 q14；JSON 做一遍散题 q1。
6. **选择题知识点**：树的插入与旋转推演、文法判断、Android 生命周期、JML、SOLID、知识产权，再加每周的选择题练习。

《零基础复习手册》原来把第 3 章（UML、SOLID、重构、开放题）排在第一位。按今年的提示，其中开放题的写作部分可以往后放；UML 读图和 SOLID 的判断仍然要看，分别用于设计模式题和选择题。

所有代码题通用的规则（各套卷的总 README 都有）：

- 代码必须能编译，否则该题零分。交卷前把每道题的测试都跑一遍。
- 不能改方法签名和已有字段，不能给方法加 `throws`；只在注释标出的区域内写代码。
- 只能用 Java 标准库、JUnit4 和题目提供的库。
- 给出的测试只是示例，评分用另一套测试，要按 README 的文字规格实现。
